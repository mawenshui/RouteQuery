# RouteQuery — Windows 列车线路查询助手

一个 **不下单、不碰凭据、只读查询** 的 Windows 桌面应用：输入出发地、目的地和日期，把 12306 官方的直达车次与换乘方案整理成本地可筛选、可比对、可钻取的结果视图，需要买票时一键跳转官方页面。

> 本工具与 12306 官方无任何关联。不采集任何个人信息；查询条件、收藏、历史只存本机。若使用内嵌官方登录页获取换乘数据，会话以 DPAPI 加密存在本机，并提供一键清除。

## 一分钟看懂这个应用

**做**：站点模糊输入 → 选日期 → 查直达（游客可用）→ 可选登录官方页查换乘方案 → 按车型/时段/席别/有无票筛选 → 按最快/最早/最便宜排序 → 点开看经停站与**几点放票** → **对买不到的车次算"多买几站"要花多少钱（上限 1–10 站可设，默认 10）** → 收藏常用线路 → 跳转官方购票。外观支持浅色/深色/跟随系统；启动时检查一次新版本（可关闭）。

**不做**：自实现账密登录、代填验证码、购票、候补提交、余票自动监控、读取订单/常旅客、**为"多买几站"提供任何自动下单或锁票**、**对中转两段分别扩展**、**计算学生/儿童票价**（数据拿不到就不算，只给说明）、多设备同步、云端服务。

**四个根本约束**：

1. 12306 没有公开 API。本应用依赖网页端非公开接口，路径与字段随时可能变化。应对方式是把列下标收敛进一张带**来源标记**的布局表，并在解析前做结构自检——**自检不过就停止出数**，不允许"猜着往下解析"。
2. **数据来源单一性**：所有列车、余票、票价、经停站数据只能来自官方接口。取不到就报错，**禁止**用码表推断、缓存冒充、常识推算或第三方补齐来"把功能保住"。这个应用的输出是亲友的出行与购票决策依据，一个看起来正常的错数字比空白危险得多。
3. **"多买几站"是本项目唯一允许"一次动作 → 十次以上官方请求"的功能**，而它恰好在官方压力最大时被使用。因此请求预算按动作分级（基础 ≤3、扩展 ≤10 硬上限 12），串行与 ≥3 秒间隔不放宽，并把每次实际请求数写进日志供发布前核对。
4. **出站只有两个目的地**：12306 官方接口，以及一个被写死边界的 GitHub 版本检查（启动一次、不带本机信息、可关闭、失败静默）。除此之外不得有任何第三方出站——包括配置下发、灰度开关、日志上传，那些会把个人工具变成有控制端的服务。

**接口的关键事实**（2026-10-09 实测，全部有代码级或逐格比对依据）：余票在**列 20–33**（列 34 是 `yp_ex`，与余票无关）；票价在**列 39**，与官方 `queryTicketPrice` 逐项一致，因此不需要额外取价；经停站端点是 `czxx/queryByTrainNo` 且**游客态可用**；`leftTicket/query` 会 302 到带后缀的路径；接续换乘 `lcQuery` **需登录**。

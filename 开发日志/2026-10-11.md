## 二、这一轮查出来的问题

按严重程度排，前三条都会让用户读到**错的数**：

| # | 问题 | 为什么会出事 | 处理 |
|---|---|---|---|
| 1 | 解析层四处"解不出来就退化成默认值"：`TimeOnly.Parse` 裸解、日期退 `DateOnly.MinValue`、时长退 `TimeSpan.Zero`、数值退 `0` | 时刻退化成 `00:00` 是把下午的车显示成凌晨；`wait_time_minutes` 退成 `0` 是"候车 0 分钟"这种凭空造的数，而且和真数据长得一样 | 改成四个严格读取器 `ReadClock/ReadDuration/ReadDate/ReadInt`，解不出来一律 `ParseFailure` 并在 detail 里点名字出字段与原始值。AGENTS 六.2 本来就写着"禁止猜着往下解析"，之前是没执行 |
| 2 | 跨两天到达仍写"次日" | `ArrivesNextDay => ArrivalDate > TravelDate` 把任何跨日都叫次日；中转是可以出现第三天到达的长路线 | 模型改成 `ArrivalDayOffset`（两个官方日期相减，不推断）；界面 0 不标、1 写"次日"、≥2 写"N天后" |

| 6 | 收藏**没有删除入口**，而"收藏已满 20 条"的提示却让用户"先删掉一条不常用的再存" | FR-16 明文要求"保存/命名/删除"，验收②是"删除一条不影响其余顺序"。存储层 `Remove` 和测试都有，唯独界面上点不到——那句话是一条做不到的指示 | 收藏行换成 `ItemTemplate`，右侧一个"删除"按钮，走 `RemoveSaved_Click`；删完在侧栏反馈位写"已删除收藏：X"。不加确认框：一条收藏点"收藏本次"一秒就能重建，误删代价几乎为零 |

| 8 | 三个文案死键 | `关于_版本` 现在用上了；`扩展_剩余额度` 与侧栏常驻的 `状态_剩余额度` 重复（额度已在侧栏显示，删键）；`中转_本版未做` 是功能做完后遗留的说明 | 删掉后两个 |

## 三、几个决定

- **不拿"测试全绿"当界面验收的替身**。今天新增的两条守卫拦得住"名字不存在"，拦不住"名字对但绑错层"和"布局塌了"。所以计划文档第 188 行那条没删，只是把范围缩小到五项具体要看的东西（见下）。
- **时刻/数值字段漂移一律停，不出数**。这会让用户偶尔看到"接口变了"而不是十条结果，看着像退步。但一个错的到达时刻的代价是上了错车，而"查不到"是可以重试的。这个取舍 AGENTS 七.5 已经替我做过决定了。
- **`day_difference` 也按严格整数解**。只见过 `"0"`，所以严格化有猜测被判死的理论风险。我选择判死：它错的方式是"少出数并说明原因"，而不是"出一个看起来对的数"。

## 七、TASK-43 起售时间：数据早就有，缺的是"到没到"这句话

列 55 上一轮就解析出来了，`JourneyRowViewModel.OnSaleText` 也在，但界面上只在**官方标记为未开售**时显示"X 月 X 日起售"。FR-33 要的是另一种口径：

| 情况 | 该显示 | 之前 |
|---|---|---|
| 官方没给这一列 | 整行不出现 | ✓ |
| 时刻未到 | "10 月 28 日 08:00 起售" | 只在未开售标记下出现 |
| 时刻已过 | "已过起售时间" | **完全没有这一说** |

补了 `HasOnSale` / `OnSaleNote`，显示位放在详情区标题行。

一个实现选择值得记：**"到没到"比较的是调用方传进来的"本次查询时刻"，不是属性内部取 `DateTimeOffset.Now`**。理由两条——一是这样能写成测试（`OnSaleDisplayTests` 用固定时刻断言三档），二是它天然是快照，不会让人误以为界面会自己变。FR-33 明文禁止定时器（到点提醒留在 V2），所以我顺手加了一条守卫：**App / Core / Data 三个工程的源码里出现 "Timer" 这个词就判失败**。这条守卫是会被误伤的（注释里写"定时器"没问题，写英文就不行），但宁可被误伤也不要哪天冒出一个 `DispatcherTimer` 把 SPEC-007 四节的"自动请求 = 0"变成一句空话。

## 九、TASK-46 检查更新：地址落点跟设计写的不一样

DEC-15 说得很清楚：独立 `HttpClient`、不进 `RequestGate`、不与官方客户端共享 `CookieContainer`。实现照做，但**地址常量没有按 v1.4 设计写的放在 `App/Update/ReleaseChecker.cs`，而是放在 `Data/Http/ReleaseFeedClient.cs`**：AGENTS 六.1 要求 App 与 Core 不得出现任何 URL，那条规则原文是针对 12306 的，但"全项目只有这一处地址"这个可审计性质对 GitHub 同样成立——把地址散到界面层，SPEC-007 六.1 的例外就没法用一条 grep 审计了。设计文档 v1.7 记了这个落点差异。

界面层 `ReleaseChecker` 只留版本比较，比较口径也想清楚写成注释：只认开头数字三段，`0.2.0` 对 `0.2.0-rc2` 算升级（rc→正式），反过来不算，两边都带后缀一律不提示。**不按字符串比**，否则 `0.10.0` 会被判成比 `0.9.0` 旧。

四条判据的落实：
- 频率：`MainViewModel` 构造末尾 fire-and-forget 一次，且只此一处；无重试、无轮询。
- 不携带本机信息：只有 GitHub API 强制要求的固定 UA `RouteQuery`。
- 可关闭：设置页新增"更新"区块，勾掉立即落盘并清掉已显示的提示。`ReleaseFeedClient` 用 `UseCookies = false` 显式声明这个客户端永远不带 Cookie。
- 失败静默：任何异常（断网、超时、被墙、不是 JSON、被取消）一律返回 null，连日志都不写——否则"检查更新失败"会在日志里长得像故障。

**但端到端没验成**：`api.github.com/repos/mawenshui/RouteQuery/releases/latest` 实测 404，仓库还没有 Release（仓库本身在，`/repos/mawenshui/RouteQuery` 返回正常，所以地址没写错）。程序行为符合设计（取不到就彻底静默），可"有新版时状态栏出现弱提示"这一条判据只能等第一个 Release 发出去再验。已记为 **K-09**，写进计划第十一节而不是被"代码写完了"消化掉。

# TASK-45 深色主题：果然不是收尾

## 十一、先说结论：代码做完了，"三档切换无对比度不足"这条**没有**判为通过

屏幕仍是锁着的（`LockApp.exe` 占前台），而 FR-35 的验收①②本质上都是**看**：
"所有页面无残留对比度不足的文字"、"125%/150% 各走查一次"。我能做的是把结构搭对、
把这类错误变成测试拦得住的东西，**不能说界面已经验证过**。

## 十二、色板三本字典，界面只认键名

- `Resources/浅色.xaml`、`Resources/深色.xaml`：只有色值，键名完全一致，各 12 个键。
- `Resources/主题.xaml`：只有样式，**一个色值都不写**，颜色一律 `DynamicResource 笔刷_X`。
- `App.xaml` 并 文案 → 主题 → 浅色；`ThemeManager.Apply(档位)` 就是把最后那本换掉。

用 `DynamicResource` 而不是 `StaticResource` 是"即时生效"的实现前提：后者在字典被换掉后不会重新求值，
设置页一改就要重启才变——而 FR-35 明写"即时生效"。

`跟随系统` 读 `HKCU\...\Themes\Personalize\AppsUseLightTheme`，只在启动和手动切换时各读一次。
不监听系统设置变化：那要么挂常驻钩子要么放定时器，而应用内**不允许出现定时器**（FR-33 同一条约束）。

## 十三、改造过程中被纠正的两处

1. **余票高亮原先是 `IValueConverter` 里造的 `SolidColorBrush`**（`Color.FromRgb(0xB3,0x54,0x1E)`）。
   那种颜色编译期就固定了，换主题不会跟着变——正是 FR-35 约束要防的"深色残留"。
   改成样式触发器 `席别文字`（`DataTrigger HasTicket=True`），并**删掉这个转换器**：留着一个已知会出错的东西比删掉它更危险。
2. **有票的高亮色是橙 `#B3541E`，不是绿**。我第一版色板把它写成绿色，是把"状态正常"那条绿（`#1B6B3A`）
   误当成了列表里的有票色。发现后把键名拆成 `笔刷_有票`（橙）和 `笔刷_成功`（绿）两个角色，浅色下与改造前逐值一致——
   **外观需求不能顺手改掉原来显示的信息含义**。

顺带把次级文字从 `#8A8A8A`（白底约 3.5:1）提到 `#6A6A6A`（约 4.9:1，过 AA）。
深色下错误色没有照搬浅色的 `#B3261E`（在 `#1B1B1E` 上只有约 2.6:1），改成提亮的 `#FF8A80`；
而那条红底白字横幅另外配了 `笔刷_错误底`/`笔刷_底上文字` 一对键——深色下拿 `#FF8A80` 当底，白字对比只剩约 2.3:1。

## 十四、新增三条主题守卫

`ThemeGuardTests`，三条都用"故意改坏"验过会失败：

- 界面文件里不许出现任何色值，**具名色也算**（`Foreground="White"` 这种按 `#` grep 会漏）。
- 两份色板的键必须一模一样。整本换字典时缺一个键**不会报错**，那段文字直接落回系统默认色——深色底上一段黑字。
- 界面用到的每个 `笔刷_X` 都必须在**两份**色板里都有，并要求"一个都不要求"时测试自己失败（防止守卫空转）。

加上原有两条：App/Core 不得出现地址字面量、三个发布工程不得出现 Timer。

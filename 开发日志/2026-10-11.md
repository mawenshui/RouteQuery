# 开发日志 2026-10-11

今天没有新功能，只有一件事：**把上一轮欠的验证补上**。上一轮结束时我在计划文档里写下"方案列表真正渲染出来的样子我一次都没看到"，这一条不能就这么过去。

## 一、屏幕锁了，于是换了个验证办法

12:24 那次实跑把中转列表渲染出来了（10 条方案、逐段席别、`票价官方未给出`），也正是那一次肉眼看到了两处错：时间用了 12 小时制、每一行都在断言"需换车站"。修完之后要复走，`computer-use` 却连续返回 `blocked_before_pointer_input`。查了一下前台窗口是谁：

```
hwnd=5181970 pid=15792 process=LockApp.exe
```

**锁屏程序占着前台**，指针输入根本送不到应用窗口。解锁是用户本人的事，我不会去绕——绕过登录界面本身就越过了这台机器的安全边界，更别说那还只是输入层面的问题。

所以今天的验证改成两条腿走：

1. **文本层面**用视图模型级测试覆盖（`TransferRowViewModel` 直接吃真实脱敏样本，断言它产出的字符串）。这一层就是昨天出错的那一层，测得住。
2. **界面层面**新增静态守卫（`XamlBindingGuardTests`）：把 XAML 里 `{Binding X}` 的属性名拿去和程序集里真实存在的公共属性对，把 `{DynamicResource 键}` 和 `text.Get("键")` 拿去和资源字典里定义过的键对。

守卫写完不能算数，因为它可能什么都没在看。所以故意把 `AboutVersionText` 改名、把一处 `DynamicResource` 改成不存在的键，两条测试都失败了并指名道姓：

```
Collection: ["中转_查无此键  ←MainWindow.xaml"]
```

**它证明的是"这个名字在代码里存在"，证明不了"绑在了正确的那一层"**——后者仍然只有肉眼看得到。这条限制写在类的注释里，不留"测试全绿 = 界面没问题"的错觉。

## 二、这一轮查出来的问题

按严重程度排，前三条都会让用户读到**错的数**：

| # | 问题 | 为什么会出事 | 处理 |
|---|---|---|---|
| 1 | 解析层四处"解不出来就退化成默认值"：`TimeOnly.Parse` 裸解、日期退 `DateOnly.MinValue`、时长退 `TimeSpan.Zero`、数值退 `0` | 时刻退化成 `00:00` 是把下午的车显示成凌晨；`wait_time_minutes` 退成 `0` 是"候车 0 分钟"这种凭空造的数，而且和真数据长得一样 | 改成四个严格读取器 `ReadClock/ReadDuration/ReadDate/ReadInt`，解不出来一律 `ParseFailure` 并在 detail 里点名字出字段与原始值。AGENTS 六.2 本来就写着"禁止猜着往下解析"，之前是没执行 |
| 2 | 跨两天到达仍写"次日" | `ArrivesNextDay => ArrivalDate > TravelDate` 把任何跨日都叫次日；中转是可以出现第三天到达的长路线 | 模型改成 `ArrivalDayOffset`（两个官方日期相减，不推断）；界面 0 不标、1 写"次日"、≥2 写"N天后" |
| 3 | 官方两个日期自相矛盾时（`arrive_date` < `train_date`）照样出数 | 那时"第几天到"根本无从确定，显示出来就是猜 | 按数据对不上丢弃并计入丢弃数，界面向用户说"另有 N 个方案数据对不上" |
| 4 | 跨日标注做了但**列表模板没绑它** | 过夜方案只显示 `06:30 到达`，读者当成当天早上——`ArrivalDayNote` 是死代码 | 模板里补上这个 Run；顺带确认模板绑的 9 个行属性都在 `TransferRowViewModel` 上 |
| 5 | 关于页的版本号是**空白** | XAML 绑 `AboutVersionText`，视图模型上只有 `AppVersion`。这是我上一轮用脚本批量改文件时"说改了其实没改"留下的 | 补上 `AboutVersionText`（用一直挂着没人用的 `关于_版本` 键）；这类静默空白正是新守卫要拦的 |
| 6 | 收藏**没有删除入口**，而"收藏已满 20 条"的提示却让用户"先删掉一条不常用的再存" | FR-16 明文要求"保存/命名/删除"，验收②是"删除一条不影响其余顺序"。存储层 `Remove` 和测试都有，唯独界面上点不到——那句话是一条做不到的指示 | 收藏行换成 `ItemTemplate`，右侧一个"删除"按钮，走 `RemoveSaved_Click`；删完在侧栏反馈位写"已删除收藏：X"。不加确认框：一条收藏点"收藏本次"一秒就能重建，误删代价几乎为零 |
| 7 | 全程票场景显示"已完成 0 / 0" | 候选集为空只有一种情况（这趟车在该区间已是全程票，前后都无站可扩），设计 §6.3 要求专门说明；`0 / 0` 会被读成功能坏了 | `RequestsIssued == 0 且 Outcomes 为空` 时显示 `扩展_全程票`；同时补上用户主动停止时显示"已取消"而不是 `0 / 0` |
| 8 | 三个文案死键 | `关于_版本` 现在用上了；`扩展_剩余额度` 与侧栏常驻的 `状态_剩余额度` 重复（额度已在侧栏显示，删键）；`中转_本版未做` 是功能做完后遗留的说明 | 删掉后两个 |

第 7 条里的"停止后显示 0 / 0"是顺手补的：同一个分支链上，用户按了停止却看到一句废话，性质和全程票那条一样。

## 三、几个决定

- **不拿"测试全绿"当界面验收的替身**。今天新增的两条守卫拦得住"名字不存在"，拦不住"名字对但绑错层"和"布局塌了"。所以计划文档第 188 行那条没删，只是把范围缩小到五项具体要看的东西（见下）。
- **时刻/数值字段漂移一律停，不出数**。这会让用户偶尔看到"接口变了"而不是十条结果，看着像退步。但一个错的到达时刻的代价是上了错车，而"查不到"是可以重试的。这个取舍 AGENTS 七.5 已经替我做过决定了。
- **`day_difference` 也按严格整数解**。只见过 `"0"`，所以严格化有猜测被判死的理论风险。我选择判死：它错的方式是"少出数并说明原因"，而不是"出一个看起来对的数"。

## 这一版修掉/新增了什么

**中转（延续 rc2，修完显示层）**
- 时间改成 24 小时制。原先 `05:00 出发`其实是 17:00——`TimeOnly` 的 `hh` 是 12 小时制且不带 AM/PM。
- 删掉每行"需换车站"的断言。`same_station`/`isOutStation` 在 10 份样本里恒为 `"0"` 而 `same_train` 是 `"Y"`，
  含义无法确定，界面就不替官方下结论（现在只说候车多久）。
- 解析层四处"解不出来就退默认值"全部改成 `ParseFailure`：时刻不再退成 `00:00`、
  候车/全程时长不再退成 `0`、日期不再退成 `DateOnly.MinValue`。这是 AGENTS 六.2"禁止猜着往下解析"的落实。
- 跨两天到达不再写成"次日"；官方两个日期自相矛盾的方案丢弃并计入"另有 N 个数据对不上"。

**新增（V1 收尾四项）**
- **起售时间**（FR-33）：详情区标题行显示"X 月 X 日 HH:mm 起售"，已过则显示"已过起售时间"，
  官方没给这一列就整行不出现。**应用内没有任何计时器**，所以不会到点提醒——那是 V2 的事。
- **票价口径说明**（FR-34）：常驻在价格列下方那一句，措辞是需求原话。学生票/儿童票**不算**，
  因为同一席别的第二条价格业务含义未确认（Q-05 残余），标成"儿童票"就是拿猜测当数据。
- **深色 / 浅色 / 跟随系统三档主题**（FR-35）：设置页切换即时生效。颜色全部收进
  `Resources/浅色.xaml`、`Resources/深色.xaml` 两本色板，界面文件里已经没有色值（含具名色）。
- **检查更新**（FR-36）：启动时经独立 `HttpClient` 向 GitHub 取一次最新版本号，
  不占官方请求额度、不带任何 Cookie、失败完全静默；设置页"更新"里可以关掉。

**修掉的界面缺陷**
- 关于页的版本号此前是一片空白（XAML 绑了一个视图模型上不存在的属性）。
- 收藏只有"存"和"用"，**没有删除入口**——而"收藏已满 20 条"的提示却让用户"先删一条再存"。
- "多买几站"在全程票场景显示"已完成 0 / 0"，现在显示专门说明；用户主动停止也不再显示 `0 / 0`。

## 我验证到哪一步（这一段请一定读）

**验到的部分**（不需要看屏幕的那部分，用 UI 自动化读控件树做完了）：
- 发布件能启动，主窗口 69 个节点齐全；设置窗口能打开，内容完整。
- 关于页读到 `版本 0.2.0-rc2`（改绑之后的验证）；发布件二进制版本戳是 `0.3.0-rc1`，
  代码里会去掉 SDK 追加的 `+commit`，所以这一版应显示 `版本 0.3.0-rc1`。
- 主题三档单选存在，存储值正确反映为"跟随系统"被选中。
- 收藏行渲染出"删除"按钮（存在性；点击后的行为没验，那要真删你的收藏）。

**没验到的部分——这一版所有验收判据里，凡是要"看"的都没做**：
这台机器从前台被 `LockApp.exe`（锁屏）占着，指针与键盘输入送不进应用。
所以下面这些**我不知道对不对**，需要你解锁后逐条走一遍：

1. **中转列表修复后的样子**：时间应是 `17:00 出发 · 21:18 到达`，且没有任何一行写"需换车站"。
2. **三档主题各切一次**，逐屏看有没有残留看不清的文字：直达列表、中转列表、经停表、扩展面板、引导态、登录窗、设置窗。
3. **深色下两处已知风险点**：红底白字那条登录横幅、以及 `ComboBox` 下拉与 `DatePicker` 日历（见 K-10）。
4. **125% 与 150% 缩放下**两种主题各走查一遍（FR-35 验收②）。
5. 选一趟全程票的车点"开始扩展"，应显示"这趟车在你查的区间已经是全程票了"。
6. 点收藏行的"删除"：应删掉这一条、其余顺序不变、下方出现"已删除收藏：X"。
7. 选中一趟车后，详情区标题行是否出现起售时间；官方没给的那趟车应该整行不出现。
8. 价格列下方那句票价说明，位置是否真的读得到（它如果该藏在设置页里就等于没做）。
9. 设置页关掉"启动时检查一次新版本"，重启后确认仍是关闭状态。

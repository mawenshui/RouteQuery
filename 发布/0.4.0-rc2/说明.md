## 这一版改了什么

### 第 10 轮：反馈与布局（FR-46 ~ FR-49）

- **统一反馈**：结果 / 提示 / 警示 / 错误四级共用一个组件形态，级别只换底色与文字色；
  位置规则写进设计——**反馈出现在引发它的动作所在区域**。
- **空结果回结果区**：官方给零趟时那句话画在直达区域正中（14 号字，与"还没有查询"同一档），
  顶部只留"查询完成"。筛选后为空同理，且"筛没了"与"官方没有"仍是两句话（AGENTS 七.6 不许合并）。
- **收藏满回侧栏**：警示级底色，写在收藏列表那块区域里，不再是左下角一行小灰字。
- **信息归位**：额度贴查询按钮、结果数贴表头右上、"设置"提到菜单一级且全站入口数 = 1（有守卫数着）。
- **席别全量呈现**：`SeatTexts.Summary` 里那个"只取前三个"的摘选删掉了，改成 `Lines()` 全列；
  每行"席别名 余票态 · ¥价"。**零额外请求**——数据本来就在同一次 `API-02` 响应里。

### 第 11 轮：票价对齐改正（TASK-73 ~ 76）

自动化验证（应用 + 官方页面同一 OD 同一日期各取一次快照）暴露的不是"显示不全"，是"价格挂错席别"：

- **记录切分改正**：票价串按官方的 `短码(1) + 角(5) + 尾部(4)` 切，此前用的是 `短码(1) + 分(6) + 附加(3)`。
  错误切分把无座那条（`O066103062`）读成"二等座的重复价 661.03"，再被"同席别取首条"整条丢掉。
  **官方判无座只看尾部 ≥ 3000，不看短码**（原文条件抄进 `PriceDecoder` 的注释）。
- **短码表整表重做**：`3`=硬卧、`4`=软卧（此前互换）、`D`=优选一等座、`A`=高级动卧、`P`=特等座、
  `J`=二等卧、`F`=动卧，官方没有 `T`。逐条出处是官方页面的 `seatTypeCodeForName` 与其 `aria-label` 生成函数。
- **最坏的一条**：K599 的硬卧被标成 102.5、软卧被标成 67.5——**一个比软卧还贵的硬卧**，
  与真数据长得一模一样。这类错误不会报错、不会被抽查发现，只会安静地误导下单决策。
- **判据从抽查升级成不变量**：`每条票价记录尾部的余票数都落在它自己那一列上`。
  两份真实样本 29 条全过；植入 `3`/`4` 互换的违例后它报出
  "K599 短码 4 尾部 2 → HardSleeper 那一列实际是 有，不是 2"。旧表在同判据下 22 条里 11 条矛盾。
  **为什么必须这样**：错误切分是自洽的，每条单独看都对得上——逐格核对过、结论写进过文档、测试也全绿，
  仍然是错的（见 SPEC-007 v1.9 对 Q-05 的改判）。

## 出包时撞出来的那条崩溃（已修，本包就是修复后的构建）

翻当日日志时看到两条 14:58 的**未处理异常**（版本头 `v0.4.0-rc1`）：

```
InvalidOperationException: The requested operation requires an element of type 'Object',
  but the target element has type 'String'.
  at RouteQuery.Data.Parsing.TransferParser.Parse(...)
  at RouteQuery.App.ViewModels.MainViewModel.RunTransferAsync(...)
```

`TransferParser` 在响应某一段是字符串而不是对象时直接抛，异常穿过 `AsyncCommand` 落到 WPF 的
分发器上——**这是本应用唯一一条没有降级路径的解析入口**，违反 AGENTS 第七节"所有网络调用必须有
超时、取消、失败降级三件套"。它跟本轮的票价改动无关（不同文件、不同接口）。

**已修（TASK-77），本包就是修复后的构建**：同一形状三处一起补（余票 `data.result`、
经停站 `data.data`、中转 `data.middleList`），分类按 AGENTS 七.6 分开——外层不是对象 /
这一项不存在 → 结构变更（该换版本）；`data` 给成一段文字 → 官方这一项没给（等一会儿或去官网看）。
判据用植入违例证明会响：第一次只把安全调用换回旧写法时测试**仍然全绿**（前面的守卫先短路了），
把守卫一起拆掉才报出日志里那个异常类型——"植入了违例"和"违例走到了那一步"是两件事。

因此本包的构建点比发布文档的首版晚一次提交。旧 zip（`6a2fbc49…`）**从未分发**（名单按用户决定留空），
换掉不算 SPEC-006 §六 的"静默替换"，但构建点与校验和的变化记在这里，不让两个 rc2 各自漂着。

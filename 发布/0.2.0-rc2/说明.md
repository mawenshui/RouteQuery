## 这一版修掉/新增了什么

- **中转查询打通**：真实路径是 `/lcquery/queryG`（不在 `/otn/` 下）。SPEC-007 v1.1 起记的
  "此接口需登录"是误判——官方对未知路径先丢给登录墙，我们把"路径不对"读成了"需要登录"。
- **登录态采集缺陷**：Cookie 匹配含路径，而该应用的 `JSESSIONID` 挂在 `/lcquery` 下。
  采集范围从"站点根路径"改为按真正要访问的几条路径各问一次取并集。
- **两端口径改正**：总历时字段是"4小时18分钟"这种中文而非 `hh:mm`（时长按分钟数取，原文只用于显示）；
  这个接口不给票价，所以那一格写"票价官方未给出"，也不按价格排中转方案。

## ⚠️ 验收时请先做这一件事

**去 12306 官网退出登录。** 上一轮排查时你贴出的请求头里含有实时会话凭据
（`JSESSIONID` / `uKey` / `tk`），那串东西已经进了对话记录。我不会把它们写进任何文件，
但它们该失效。退出后在应用里重新登录一次即可（内嵌登录页用的是同一个私有目录）。

## 请重点看这几条（我没能自己看到的）

1. **中转列表渲染出来的样子**。解析层用真实样本测过（10 个方案逐字段核对），页签和按钮也由
   UI 自动化确认可点，但点的那一次两站是空的、走了"请先选站"分支，紧接着机器锁屏——
   **方案列表真正显示出来的样子我一次都没看到**。填好两站 → 中转页签 → 查换乘方案。
2. 中转行里"票价官方未给出"是否够显眼（不能让人以为免费）。
3. 换乘文案是否说清了三件事：候车多久、是否同站、是否需要出站再进站。
4. 会话被官方拒绝时：应回到"请先登录"的引导态而不是红色报错，且本地会话已被清除。
5. 官方给出 0 个方案时（冷门 OD）应显示"没有"，与"解不出来"（报错）是两种不同说法。

## 这一版改了什么：站点码表从"旁边的文件"变成"打进 exe"

之前 rc1/rc2 的包是 `RouteQuery.exe` + `Resources/stations.json`，SPEC-006 的发布物清单里从来没这一项——
**那是我自己偏离规范的结果**，代价落在亲友身上：只拷 exe 出去就会每次查询都报"内置站点数据读不出来"，
而 `使用说明` 只能写成"请整个文件夹一起解压"这种预防性叮嘱。

现在：

- `src/RouteQuery.Data/Resources/stations.json` 改成 `<EmbeddedResource>`，由数据层程序集带着它；
- `StationTableLoader.LoadBundled()` 从程序集清单资源读，**不再读文件**（顺带删掉那个从来没人传参的 `baseDirectory` 参数）；
- 装载优先级不变：**先读你手动更新过的那份**（`%LOCALAPPDATA%\RouteQuery\stations.json`），
  没有或校验不过才退回内置副本（FR-18 验收②"更新失败绝不能让应用不可用"照旧成立）；
- 新增一条测试 `内置码表是嵌在程序集里的而不是旁边的文件`，守的就是打包形态本身——
  一旦 csproj 那行被改回 `CopyToOutputDirectory`，测试立刻红。这类回归在开发机上完全看不出来。

exe 体积 +393 KB（163,099,398 → 163,492,102），压缩包体积基本不变。

**实测**：把 exe 单独拷到一个空目录（没有任何伴生文件）、并把本机 `%LOCALAPPDATA%` 里那份更新过的表临时移开，
程序正常启动，状态栏显示 `站点数据日期 2026-10-10` —— 供数的就是内置副本。看完后已把那份表放回原位。

## 站点码表是什么、为什么要更新、怎么更新

**是什么**：一张"站名 ↔ 官方三字码"的对照表，约 3400 条，含全拼、简拼、所属城市。
12306 的接口认三字码不认汉字（北京南 = `VNP`、上海虹桥 = `AOH`），所以打字联想、显示站名、
经停站对齐、发请求前校验"这站存不存在"，全都依赖它。**它现在嵌在 exe 里**，断网也能完成一次查询。

**为什么要更新**：车站会改名、会新开通。内置这份是 **2026-10-10** 从官方 `station_name.js` 取的。
表过期最典型的症状是"某个站怎么搜都搜不到"。超过 90 天设置页会出现一行小字提示（FR-18）。

**怎么更新**：设置页 →「站点数据」→「更新站点数据」。取回来**先校验条数够不够，够才替换**；
断网或数据不全都会保留原来那份并说明原因。**换好后要关掉程序重开一次才生效**，界面会明说。
更新下来的表写到 `%LOCALAPPDATA%\RouteQuery\stations.json`，内置那份不动、也不被覆盖。

## 已知问题

K-03 / K-04 / K-05 / K-07 不变。
**K-09 仍然开着，而且原因比我原先写的更硬**（下面是发布后实测的，不是推断）：
第一个 Release 已建好（`v0.3.0-rc3`，附件即本包），但应用问的 `releases/latest` **仍然返回 404**——
GitHub 这个端点按定义排除预发布版本。更要紧的是第二层：即使它返回了 `v0.3.0-rc3`，
我们的比较规则**故意不把 rc→rc 当成升级**（两边都带后缀一律不提示，见 `ReleaseChecker` 注释），
所以提示也不会出现。这条判据只能等**第一个正式版标签（v1.0.0）**对一个 rc 构建体出现时才验得到。
推论：发布 v1.0.0 时**不要勾 prerelease**，否则检查更新功能整体等于没做。
**K-10 部分解决**：深色档下 `ComboBox`、`DatePicker`、页签条、滚动条仍是系统浅色外观——读得清，不统一。
界面复走还剩：125%/150% 缩放两主题各一次、关掉检查更新后抓包确认零非官方出站。

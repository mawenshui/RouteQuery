## 一、窗口与分区

单窗口，最小尺寸 `1080 × 640`，默认 `1280 × 800`。不允许出现"页面跳转"，所有交互在同一窗口内就地完成。

| 区域 | 高度 | 内容 |
|---|---|---|
| 查询栏 | 64 px | 出发站（220）· 到达站（220）· 互换按钮（32）· 日期（150）· 查询（96）· 取消（72，仅查询中可见） |
| 筛选栏 | 44 px | 车型 ▾ · 时段 ▾ · 席别 ▾ · ☑ 只看有票 · ☑ 当天到达 · 清除筛选（右侧，无生效条件时置灰） |
| 结果区 | 自适应（主体） | 页签"直达 / 中转"，下方为列表或卡片 |
| 侧栏 | 默认宽 210 px，**可拖宽（最小 160）、可整体隐藏** | 常用线路（≤20）· 最近查询（≤30） |
| **顶部条**（v1.3，取代原底部状态栏） | 34 px | 左：菜单栏（文件 / 视图 / 主题 / 帮助）；右：站点数据日期 + **更新站点数据按钮** · 状态一句话 · **今日还可查询 N 次** · 新版本弱提示 · 非官方声明 · 设置 |
| 详情区 | 默认高 280 px，**可拖高（最小 120）、可整体隐藏** | 经停时刻表 + 多买几站 |

**为什么顶部条必须带登录状态与剩余额度**：应用持有的是亲友本人的 12306 会话，把它放在只有设置页能看到的地方等于把风险藏起来（FR-25、RISK-18）；而 v1.3 起"选中车次就会取一次经停"（FR-43），额度消耗从"点按钮"挪到了"点行"，**用户必须随时看得见自己正在花什么**——所以"今日还可查询 N 次"从原来的加载态专属提升为常驻。

**底部不再有状态栏**（FR-41）。原来贴在底部的三样东西（站点日期、状态、声明）全部上移到顶部条右侧，一行读完。

## 一·五、顶部条与菜单栏（FR-41，v1.3 新增）

一行两半：左半是 `Menu`，右半是信息条。**不用第二行**——多一行就少一行给列表，而列表是本应用唯一的主角。

| 菜单 | 项 | 行为 |
|---|---|---|
| 文件 | 更新站点数据 | 与顶部条上那个按钮同一个命令（`UpdateStationsCommand`），不另写一份逻辑 |
| 文件 | 清空本机数据 | 打开设置页的对应区块，**不在菜单里直接删**——删除必须走 FR-22 的二次确认 |
| 文件 | 退出 | 关窗 |
| 视图 | 侧栏 / 筛选栏 / 详情区 / 顶部信息 | 四项勾选式显隐（`MenuHeader` + `IsCheckable`），与面板右上角的 ▾ 按钮改的是同一个布尔值 |
| 主题 | 跟随系统 / 浅色 / 深色 | 与设置页三档**同一个状态**，切换后两处显示同步（不出现两处不同步） |
| 帮助 | 设置 / 查看新版本发布页 / 再看一次声明 | 都是已有能力的第二个入口，不新增行为。**没有单列"关于"**：关于本来就写在设置页最后一段里，再开一个窗口等于让同一个信息有两个版本 |

信息条从左到右：`站点数据日期 2026-10-10` + **[更新站点数据]** · 状态一句话 · `今日还可查询 N 次` · 有新版本时才出现的弱提示 · 非官方声明 · [设置]。

**更新码表之后必须弹窗**（FR-18 联动）：更新成功 → 弹一句"新数据要用上得重启一次"，给**立即重启**与**稍后再说**两个按钮。
选立即重启＝先起一个新进程、再退出当前进程；**不得**在用户正在读结果时不打招呼就重启。
更新失败**不弹**这个框，也**不得**显示成功措辞——照 FR-18 只说失败原因并保留旧表。

## 一·六、分隔器与面板显隐（FR-40，v1.3 新增）

| 分界 | 方向 | 默认 | 边界 |
|---|---|---|---|
| 侧栏 ↔ 主区 | 横向拖宽度 | 210 px | 侧栏最小 160；主区最小由整窗 `MinWidth=1080` 兜住 |
| 结果区 ↔ 详情区 | 纵向拖高度 | 280 px | 详情区最小 120（标题条必须始终看得见，否则用户不知道那块去哪了） |

- 分隔器宽 6 px，中间画一道 grip（三条短线），悬停时换成 `笔刷_控件边界`——**一根能拖的细线必须看得出来能拖**，否则它只是一条装饰线。
- 面板隐藏时分隔器一并消失，不留"能拖但拖不出任何东西"的空条。
- **显隐与尺寸不持久化**：重启回到默认。这是临时看数据的调整，不是偏好设置；FR-22 的原始约束是"不做多余开关"，把 `SidebarWidth` 写进设置页正是它要防的那种膨胀。
- 查询栏与结果区**不提供隐藏**。能给应用关成白屏的开关不是功能。
- 与 FR-43 的接口：详情区被隐藏时，选中车次**不**自动取经停（花额度却看不见是纯浪费）；此时点某行的"经停站"按钮，**先把详情区显示出来**再取数。

## 二、查询栏交互细节

### 站点输入框

| 时机 | 行为 |
|---|---|
| 输入 ≥ 1 字符 | 300 ms 内出候选下拉（最多 12 条），键盘 ↑↓ 可选、回车确认、Esc 关闭 |
| 无候选 | 下拉显示"未找到该车站，可能未被收录，试试站名中的一个字或上级市名"——**不显示空列表**，空列表等于让用户自己猜 |
| 选中 | 输入框显示"站名"，内部持有三字码；**界面任何位置不出现三字码** |
| 同城多站 | 候选必须逐条显示全称（北京 / 北京南 / 北京西 / 北京朝阳），**不得合并成"北京"**（FR-01 边界） |
| 已选后再次输入 | 清空旧值并重新联想，避免"看着像北京其实是北京南"的残留状态 |
| **唯一命中自动选定**（FR-45，v1.3） | 文字改变后按顺序判：① 与某站**站名完全相同** → 选它；② 候选**恰好 1 条** → 选它；③ 其余（0 条，或 ≥2 条且无同名）**一律不选**，照旧等用户点。自动选定后框里显示的就是被选中的站名、候选弹层收起、**不发任何请求、不改结果区**。理由："北京"命中北京/北京南/北京西，替用户挑一个并据此发查询，等于把一次猜测定格成一张看起来完全正常的结果（NFR-18 反对的正是这个形状） |
| **取得焦点即展开候选**（FR-39，v1.3） | 两个站名框是可编辑下拉框：点文字区必须仍是"放光标继续打字"，所以这里不改成"点哪都展开"，而是**一进焦点就把候选铺开**（用户本来就要打字）。点箭头照常开合 |
| 校验没过（FR-04） | **出问题的框标红**，且措辞指名到框：没选出发站说"请先选定出发站"、没选到达站说到达站、两站相同则**两个框一起红**（问题在这一对上，只红一个会把人引向错误的框）。三个入口（直达查询、中转、收藏）共用同一条判断与同一套文案——同一个毛病不该在三个页签里长出三种说法 |

### 日期

- 三个快捷按钮：今天 / 明天 / 后天；范围外日期置灰不可点（FR-03）。
- 每个日期后附星期，帮人判断要不要请假。
- 界面上显示一行小字："可查范围为今天起 N 天内"——N 来自配置，不硬编码（Q-02）。

### 查询按钮

- 查询进行中：文案变"查询中…"并禁用，避免重复触发；同时"取消"出现。
- 3 秒内二次点击：按钮不置灰，而是弹出提示"稍等几秒再查询"（FR-04/FR-07），让用户知道是被节流而不是程序卡住。

## 三、直达列表

行高 44 px，列顺序按"决策重要性"排：

```
车次号(含车型色标) │ 出发时刻+站 │ 到达时刻+站 │ 历时 │ 席别余票摘选 │ 最低价 │ [展开]
```

- 跨零点：到达时刻后缀"次日"，用文字而非仅靠颜色（NFR-06）。
- 车型色标**必须**同时带车次号首字母（G/D/C/Z/T/K），不允许只用颜色区分（NFR-06）。
- 席别摘选显示前 3 个有代表性的席别，格式如 `二等 有 · 一等 候补 · 商务 3`；候补与有票**必须是不同措辞**，不能都显示成绿色。
- 窗口收窄到 900 px 时按优先级折叠：先隐席别摘选 → 再隐到达站名（留时刻）→ 车次号与两时刻永不折叠。

### 常驻表头（FR-42，v1.3 新增）

```
车次 │ 出发 │ 到达 │ 历时 │ 席别余票 │ 最低价 │ 操作
```

- **表头不随纵向滚动滚走**。实现方式：给这个列表单独做 `ControlTemplate`——表头那一行画在 `ScrollViewer` **外面**，`ItemsPresenter` 在里面。
  这样表头与数据行同宽、同一个 `*` 列分配，不会出现"表头对齐了行没对齐"。
  **不用 `GridView`**：它的列宽不支持 `*`，而席别余票这一列必须吃掉剩余宽度（FR-09 的"首屏不横向滚动"判据依赖它）。
- **列宽必须与行模板同源**：两处各自写一遍数字迟早漂。仓库里加一条静态守卫，逐列比对表头与行模板的 `Width` 序列，不一致就判红。
- **表头即排序入口**（FR-12 从 v1.0 就写着"点击列头排序"，此前根本没有列头可点——**本轮补的是欠项**）：
  `出发` → 最早出发 / 最晚出发（再点切换方向），`到达` → 到达最早，`历时` → 历时最短，`最低价` → 最低价。
  当前生效列要显示方向标记（▴/▾），且排序结果与用排序下拉框选同一键**逐条一致**——两处共用同一个 `SortKey`，不各存一份。
- `车次`、`席别余票`、`操作` 三列表头**不响应点击**：席别不是一个可比较的单一值，给它排序等于自造口径。
- 表头文字承载信息，按**正文**判据过 AA（FR-38 的门槛适用于它），两档主题都要看。
- 中转页签**不做表头**：它是卡片式多行内容（每段还能各自展开），硬加表头会误导成"列对齐可比对的表"。

### 选中即显示经停（FR-43，v1.3 新增）

| 事件 | 行为 |
|---|---|
| 点选一行 | 直接取该车经停并填进详情区；标题行写"车次 · 经停站与多买几站"，起售时间照 FR-33 跟在后面 |
| 换选另一行 | **取消上一趟的在途请求**（FR-08 同口径：迟到响应不得落到新车次上），再取新车次 |
| 同一趟再次选中 | 本次运行内已经取到过的**直接用手里那份，不再发请求**（缓存挂在行视图模型上，天然按"这一趟 + 这一次查询"生效，不会跨日期跨 OD 复用错数据） |
| 在未选中的行上点"经停站" | 选中它并取数——**选中与按钮两条路都能到达，互不依赖**（用户原话："这两项内容无需强关联"） |
| 详情区被隐藏时选中 | **不取**（见 §一·六） |

预算与合规：每次选中最多 1 个 `API-04` 请求，3 秒间隔与日额度照旧由闸门管；被限制时如实提示。
**不得**为了"连点选不抖"加去抖定时器——本应用内不允许存在任何定时器。

### 展开区（互斥）

一个车次同时只能展开一个面板：经停时刻表 **或** 多买几站候选。展开新的自动收起上一个。

**经停时刻表**：站序 · 站名 · 到时 · 发时 · 停留；当前查询 OD 两站高亮并在左侧加标记（▲ 上车站 / ▼ 下车站）。数据取不到时整块显示错误提示，**不显示空表**。

**多买几站面板**：

```
┌ 多买几站（上限 5 站）│ 预计约 15 秒 │ 本日剩余额度 84 次      [停止]
│ ▓▓▓▓▓░░░░░ 6 / 12
├──────────────────────────────────────────────────────────────
│ 多买 1 站  北京西→保定东+1站   二等座  ¥58.5   多花 ¥9.5   有票
│ 多买 2 站  …                   二等座  ¥67.5   多花 ¥18.5  有票
│ 多买 1 站  …（前移）            二等座  —       无法计算     此区间不售
├──────────────────────────────────────────────────────────────
│ 还有 3 个候选未查询   [继续查询]   [到官方查这一程]
└ 政策提示（首次展开，之后收进 ⓘ）：多买区间属自愿弃用、不退款…
```

四个必须存在的元素：**预估耗时**（让用户自己决定要不要开始）、**剩余额度**（把成本透明化）、**停止按钮**（且停止后已有结果保留）、**"还有 M 个未查询"**（不假装已穷举）。

## 三·五、中转卡片与分段展开（FR-06 / FR-15）

一行一个方案：`车次对`｜`出发→中转→到达`｜`全程历时`｜`段一 / 段二`｜`票价口径`。
票价那一格写"票价官方未给出"而不是留空——留空会被读成免费。

**两段各自带一个"经停站"按钮，各自展开**（FR-15 验收原话：互不干扰）：

| 行为 | 规定 |
|---|---|
| 点某段的"经停站" | 只展开那一段，另一段的状态一个字都不动。两段可以同时展开对着读——这是共用一块详情面板做不到的 |
| 再点一次 | 收起。**不发请求** |
| 收起后再点开 | 用手里的结果重新展开。**不发第二次请求**（官方额度是共享同一个 IP 的，不该为一次点击花两次） |
| 取不到 | 错误只写在这段自己的位置上，一句人话（"官方未返回该车次的经停信息"这一类），**不显示空表**——空表会被读成"这趟车只停两站"（NFR-18） |
| 高亮 | ▲/▼ 按**该段自己的两站**标，不按整程 OD 标。按整程标会把段二的上车站标错 |
| 段标题 | 展开时该段标题里写出"车次 · 区间 · 该段乘车日期"。日期必须露出来：第二段常常已经在中转站过完夜，用户要能看出这张时刻表是从哪天取的 |
| 扩展入口 | 中转段**没有**"多买几站"（不做清单⑤）。用例 TC-D10 连带验这一条 |

按钮文案随状态改：收起时"经停站"，已展开时"收起经停"——同一个按钮在两种状态下写同一句话，
用户会以为自己没点到。

## 四、状态与文案（措辞是给亲友看的，不是给开发者看的）

| 状态 | 触发 | 主文案 | 辅助动作 |
|---|---|---|---|
| 加载 | 查询中 | 正在向官方查询… | 取消 |
| 有结果 | 正常 | — | 筛选/排序/展开 |
| 无结果 | 官方返回空数组 | "这个日期没有直达车次" | 换日期 · 看看中转 |
| 筛选后空 | 本地筛选致空 | "当前筛选条件下没有车次" | 清除筛选 |
| 引导（未登录） | 中转页签且无会话 | "不登录也能查直达。登录 12306 账号可看官方换乘方案。" | 登录 · 到官方查询 |
| 网络不可用 | 连接层失败 | "连不上网络，检查一下这台机器的网络再试。" | 重试 |
| 超时 | > 15 秒 | "官方响应有点慢，这次查询先取消了。" | 重试 |
| 疑似风控 | 非 JSON / 异常页 | "官方查询暂时不可用，过几分钟再试（不是你的网络问题）。" | **无重试按钮** |
| 结构变更 | 自检不过 | "官方数据格式有变化，这个版本查不了，请找我要新版。" | 查看版本号 |
| **数据缺失** | `DataUnavailable` | "官方没有返回这趟车的经停信息，所以算不了多买几站。" | 跳官方核对 |

两条措辞纪律：

1. **`无结果` 与 `出错` 的视觉必须不同**，`数据缺失` 与 `出错` 也不同。前者是有效信息，后两者是"我们没拿到"——把它们混成一个红色感叹号，用户就只能靠猜来判断该等、该重试还是该找我。
2. 每条文案都是"**发生了什么 + 下一步做什么**"。禁止出现英文、异常类型名、接口编号（`API-02` 这类只存在于文档和日志里）。

## 五、可访问性与缩放

- DPI 100% / 125% / 150% 三档截图走查（TC-U11）；文字不截断、按钮不重叠。
- 正文 ≥ 12 px；正文对比度 ≥ 4.5:1。
- 所有仅用颜色表达的状态一律附文字（车型色标带首字母、余票三态不同措辞）。
- 键盘可完成主链路：Tab 到输入框 → 输入 → ↓ Enter 选站 → Tab 到查询 → Enter。

## 六、视觉取向（v1.2 改写：从"装饰为零"改为"渐变皮肤但有边界"）

设计阶段的产出到"布局 + 状态 + 文案"这一层就够了，理由是：这个界面的信息结构在需求与设计里已经完全定死，不存在需要靠视觉稿来讨论的设计自由度；而 WPF 的组件与主题适配要在真实运行时才看得出问题（DPI、字体回退、虚拟化列表的实际行高）。画一套 Figma 再照着实现，会把一次就能调对的事情拆成两次。**这一条不变。**

**变的是下面这段。** v1.0 这里写的是"信息密度优先，装饰为零……不加渐变"，2026-10-13 用户明确要求换成浅色系渐变皮肤，并要求每个控件都有渐变。原话照抄在这里，是为了让以后有人问"这条是谁改的"能查到：

> ~~不加插画、不加动效、不加渐变——这些对"查完就走"的工具没有价值，只会让 3404 个站名和几十趟车的数据更难读。~~
> → **v1.2 起：渐变做，但只作为"层次提示"而不是"装饰"；可读性判据高于观感**（FR-38）。

保留下来的那一半（这些**仍然不做**）：不加插画、不加动效、不加阴影层叠、不改字号体系、不改列顺序与折叠优先级、不改任何措辞。

## 六·五、渐变皮肤的规范（FR-38）

### 1. 渐变只承担三件事

| 用途 | 规则 |
|---|---|
| 分层 | 由外到内**越往里越亮**：窗口底 → 内容底 → 卡片/输入框。渐变方向统一取纵向，同屏内所有控件同向——方向不一致会变成视觉噪声 |
| 可点击 | 只有按钮、页签选中态、链接式入口用带色相的渐变。**中性灰渐变一律表示"不可点"** |
| 状态 | 余票三态、错误、`官方未给出` 的底色允许同色系微渐变，但**语义仍由文字承担**（NFR-06）：渐变不得把"候补"和"有票"拉成同一视觉重量 |

### 2. 对比度门槛（可执行，不是口号）

- 正文（13px）与其所在底：**渐变两端分别 ≥ 4.5:1**。
- 大字（≥18px 或 ≥14px 粗体）、图标、边框与相邻底的边界：**两端分别 ≥ 3:1**。
- **必须按两端分别算，不能只算中间色**——渐变两端色差越大，"中间达标、端点跌破"正是这类改造最常见的失败形态。守卫测试按这条实现（`ThemeGuardTests`）。
- 数据密集区（结果列表行、经停表行）允许的渐变幅度上限：**两端相对亮度差 ≤ 0.04**。超过这个幅度，一行 40+ 个字段的扫读会开始变成逐字找——这是本条唯一"宁可难看也要好读"的退让。

### 3. 必须重写模板才能吃到渐变的控件

系统模板把这些控件的底色画在自己内部，外部只设 `Background` 不生效。用户选了"每个控件都有渐变"，所以下面这一串**必须一起做**，同时也把 K-10 关掉：

| 控件 | 要重写的部分 |
|---|---|
| `Button` | 常态 / hover / pressed / disabled 四态底与边框；禁用态**不得**靠透明度把文字糊掉 |
| `ComboBox` | 可编辑框、下拉切换按钮、**弹出层与其条目**的悬停与选中态 |
| `DatePicker` | 输入框、下拉按钮、**日历弹层**（`CalendarItem` 的表头/星期行/今日/选中） |
| `ScrollBar` | 轨道、滑块、两个箭头按钮，**横竖两向各一套** |
| `TabItem` | 未选 / 选中两态都要跟随主题（v1.0 时页签条整条是系统浅色，是妥协不是设计） |
| `TextBox` / `ListBox` / `ListView` / `ListBoxItem` / `ListViewItem` | 底色、行悬停、行选中 |
| `GroupBox` | 标题条与内容底。`Expander` 已随 v1.3 的详情区改造移除（分隔器要的是像素行高，与 Expander 的 Auto 收起相冲），样式与它的运行时守卫用例一并删掉，不留没人用的样式 |
| `CheckBox` / `RadioButton` | 文字色（勾选框本体保留系统画法，**不重画**——重画容易与辅助功能语义打架） |

两档色板的键名**必须完全一致**：切换主题是整本换掉，漏一个键不会报错，只会让那段文字落回默认色（深色底上一段黑字，正是 FR-35 验收①要拦的）。

### 3·五、浅色档加深（FR-44，v1.3 新增）

用户反馈"当前配色过浅"。加深的口径不是"把颜色调浓"，而是**把层次拉开**：

| 要加深的 | 不要动的 |
|---|---|
| 窗口底与卡片底的明度差（现在几乎贴在一起，看不出哪块是面板） | 正文与次级文字的**相对关系**（次级仍然要能读成"次要"） |
| 控件轮廓 `笔刷_控件边界`（输入框、按钮、下拉、表头边框） | 行底与表格文字——数据区永远优先于装饰 |
| 按钮、页签、徽标的色相饱和度 | 任何措辞、字号、列顺序 |
| 提醒底与错误底的色相浓度（弱提示不能弱到看不见） | 深色档的语义色（有票橙 / 成功绿 / 错误红）不动 |

**硬约束**：加深之后 FR-38 的三条判据一条都不能放松——正文与次级文字对所在底**渐变两端**分别 ≥4.5:1、
控件边界对内容底 ≥3:1、行底两端亮度差 ≤0.04。如果某支底加深后过不了 AA，
**正确做法是同时加深那支文字色或把这支底回退**，不是把门槛调低。
这条写在守卫里，改不动。

**本轮新出现的每一处控件都必须吃主题样式**：`Menu`、`MenuItem`、可勾选菜单项、表头单元格、`GridSplitter`。
判据两条：界面文件里不得出现硬编码色值（既有守卫），样式字典里每个新控件类型都有隐式样式（本轮新增守卫）。

### 4. 缩放

100% / 125% / 150% 三档下：不裁字、不破版、渐变不出现条纹或带状断层（斜向渐变在分数缩放下最容易出条纹，这也是方向统一取纵向的第二个理由）。

## 一、窗口与分区

单窗口，最小尺寸 `1080 × 640`，默认 `1280 × 800`。不允许出现"页面跳转"，所有交互在同一窗口内就地完成。

| 区域 | 高度 | 内容 |
|---|---|---|
| 查询栏 | 64 px | 出发站（220）· 到达站（220）· 互换按钮（32）· 日期（150）· 查询（96）· 取消（72，仅查询中可见） |
| 筛选栏 | 44 px | 车型 ▾ · 时段 ▾ · 席别 ▾ · ☑ 只看有票 · ☑ 当天到达 · 清除筛选（右侧，无生效条件时置灰） |
| 结果区 | 自适应（主体） | 页签"直达 / 中转"，下方为列表或卡片 |
| 侧栏 | 宽 240 px，可折叠 | 常用线路（≤20）· 最近查询（≤30） |
| 状态栏 | 28 px | 站点数据更新日期 · **登录状态 + 清除** · 版本号 · 非官方声明 |

**为什么状态栏必须有登录状态**：应用持有的是亲友本人的 12306 会话。把它放在只有设置页里能看到的地方，等于把风险藏起来（FR-25、RISK-18）。

## 二、查询栏交互细节

### 站点输入框

| 时机 | 行为 |
|---|---|
| 输入 ≥ 1 字符 | 300 ms 内出候选下拉（最多 12 条），键盘 ↑↓ 可选、回车确认、Esc 关闭 |
| 无候选 | 下拉显示"未找到该车站，可能未被收录，试试站名中的一个字或上级市名"——**不显示空列表**，空列表等于让用户自己猜 |
| 选中 | 输入框显示"站名"，内部持有三字码；**界面任何位置不出现三字码** |
| 同城多站 | 候选必须逐条显示全称（北京 / 北京南 / 北京西 / 北京朝阳），**不得合并成"北京"**（FR-01 边界） |
| 已选后再次输入 | 清空旧值并重新联想，避免"看着像北京其实是北京南"的残留状态 |

### 日期

- 三个快捷按钮：今天 / 明天 / 后天；范围外日期置灰不可点（FR-03）。
- 每个日期后附星期，帮人判断要不要请假。
- 界面上显示一行小字："可查范围为今天起 N 天内"——N 来自配置，不硬编码（Q-02）。

### 查询按钮

- 查询进行中：文案变"查询中…"并禁用，避免重复触发；同时"取消"出现。
- 3 秒内二次点击：按钮不置灰，而是弹出提示"稍等几秒再查询"（FR-04/FR-07），让用户知道是被节流而不是程序卡住。

## 三、直达列表

行高 44 px，列顺序按"决策重要性"排：

```
车次号(含车型色标) │ 出发时刻+站 │ 到达时刻+站 │ 历时 │ 席别余票摘选 │ 最低价 │ [展开]
```

- 跨零点：到达时刻后缀"次日"，用文字而非仅靠颜色（NFR-06）。
- 车型色标**必须**同时带车次号首字母（G/D/C/Z/T/K），不允许只用颜色区分（NFR-06）。
- 席别摘选显示前 3 个有代表性的席别，格式如 `二等 有 · 一等 候补 · 商务 3`；候补与有票**必须是不同措辞**，不能都显示成绿色。
- 窗口收窄到 900 px 时按优先级折叠：先隐席别摘选 → 再隐到达站名（留时刻）→ 车次号与两时刻永不折叠。

### 展开区（互斥）

一个车次同时只能展开一个面板：经停时刻表 **或** 多买几站候选。展开新的自动收起上一个。

**经停时刻表**：站序 · 站名 · 到时 · 发时 · 停留；当前查询 OD 两站高亮并在左侧加标记（▲ 上车站 / ▼ 下车站）。数据取不到时整块显示错误提示，**不显示空表**。

**多买几站面板**：

```
┌ 多买几站（上限 5 站）│ 预计约 15 秒 │ 本日剩余额度 84 次      [停止]
│ ▓▓▓▓▓░░░░░ 6 / 12
├──────────────────────────────────────────────────────────────
│ 多买 1 站  北京西→保定东+1站   二等座  ¥58.5   多花 ¥9.5   有票
│ 多买 2 站  …                   二等座  ¥67.5   多花 ¥18.5  有票
│ 多买 1 站  …（前移）            二等座  —       无法计算     此区间不售
├──────────────────────────────────────────────────────────────
│ 还有 3 个候选未查询   [继续查询]   [到官方查这一程]
└ 政策提示（首次展开，之后收进 ⓘ）：多买区间属自愿弃用、不退款…
```

四个必须存在的元素：**预估耗时**（让用户自己决定要不要开始）、**剩余额度**（把成本透明化）、**停止按钮**（且停止后已有结果保留）、**"还有 M 个未查询"**（不假装已穷举）。

## 四、状态与文案（措辞是给亲友看的，不是给开发者看的）

| 状态 | 触发 | 主文案 | 辅助动作 |
|---|---|---|---|
| 加载 | 查询中 | 正在向官方查询… | 取消 |
| 有结果 | 正常 | — | 筛选/排序/展开 |
| 无结果 | 官方返回空数组 | "这个日期没有直达车次" | 换日期 · 看看中转 |
| 筛选后空 | 本地筛选致空 | "当前筛选条件下没有车次" | 清除筛选 |
| 引导（未登录） | 中转页签且无会话 | "不登录也能查直达。登录 12306 账号可看官方换乘方案。" | 登录 · 到官方查询 |
| 网络不可用 | 连接层失败 | "连不上网络，检查一下这台机器的网络再试。" | 重试 |
| 超时 | > 15 秒 | "官方响应有点慢，这次查询先取消了。" | 重试 |
| 疑似风控 | 非 JSON / 异常页 | "官方查询暂时不可用，过几分钟再试（不是你的网络问题）。" | **无重试按钮** |
| 结构变更 | 自检不过 | "官方数据格式有变化，这个版本查不了，请找我要新版。" | 查看版本号 |
| **数据缺失** | `DataUnavailable` | "官方没有返回这趟车的经停信息，所以算不了多买几站。" | 跳官方核对 |

两条措辞纪律：

1. **`无结果` 与 `出错` 的视觉必须不同**，`数据缺失` 与 `出错` 也不同。前者是有效信息，后两者是"我们没拿到"——把它们混成一个红色感叹号，用户就只能靠猜来判断该等、该重试还是该找我。
2. 每条文案都是"**发生了什么 + 下一步做什么**"。禁止出现英文、异常类型名、接口编号（`API-02` 这类只存在于文档和日志里）。

## 五、可访问性与缩放

- DPI 100% / 125% / 150% 三档截图走查（TC-U11）；文字不截断、按钮不重叠。
- 正文 ≥ 12 px；正文对比度 ≥ 4.5:1。
- 所有仅用颜色表达的状态一律附文字（车型色标带首字母、余票三态不同措辞）。
- 键盘可完成主链路：Tab 到输入框 → 输入 → ↓ Enter 选站 → Tab 到查询 → Enter。

## 六、为什么 V1 不出高保真视觉稿

设计阶段的产出到"布局 + 状态 + 文案"这一层就够了，理由是：这个界面的信息结构在需求与设计里已经完全定死，不存在需要靠视觉稿来讨论的设计自由度；而 WPF 的组件与主题适配要在真实运行时才看得出问题（DPI、字体回退、虚拟化列表的实际行高）。画一套 Figma 再照着实现，会把一次就能调对的事情拆成两次。

V1 的视觉取向定得很窄，实现时照着做即可：**信息密度优先，装饰为零**。白/浅灰底，正文深灰，强调色只有一种（用于"可点击"与"当前选中"），状态色只用于余票三态与错误。不加插画、不加动效、不加渐变——这些对"查完就走"的工具没有价值，只会让 3404 个站名和几十趟车的数据更难读。

若后续要做视觉稿，放在本目录（`设计/界面/`）并按 SPEC-002 命名，不要新建目录。

## 一、版本号规则

采用 `主.次.修订`（`1.2.0`），语义如下：

| 位 | 递增条件 | 亲友侧含义 |
|---|---|---|
| 主 | 数据格式大改、界面重构、不再兼容旧配置文件 | 需要重新设置一次 |
| 次 | 新增功能（新的筛选维度、新的方案类型） | 直接覆盖安装即可 |
| 修订 | 缺陷修复、**12306 接口字段/路径适配** | 建议尽快更新，旧版可能查不出结果 |

预发布用 `-rc1`、`-rc2`，只在自家机器上用，不发给亲友。

版本号**必须**唯一来源：`src/RouteQuery.App/AssemblyInfo` 或 `.csproj` 的 `<Version>`，界面"关于"页读取同一来源。禁止在文案里手写版本号字符串。

## 二、版本控制约定

当前目录尚未初始化 Git 仓库。**第一步**就是建仓（需用户确认后执行），因为本规范的一切可追溯性都建立在提交历史上。

### 分支策略（个人/小团队规模，保持极简）

```
main            始终是可发布的状态
  └── dev       日常集成分支
        └── feat/<英文短名>   单个功能，完成即合回 dev
```

- 不长期存在的实验分支，生命周期不超过 3 天。
- 修复 12306 接口变更走 `fix/api-<日期>`，合入后立刻发修订版。

### 提交信息格式（Conventional Commits，中文描述）

```
<类型>(<范围>): <一句话中文描述>

<可选正文：为什么这么改，而不是改了什么>
```

类型取值固定：

| 类型 | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `adapt` | **适配 12306 接口变化**（本项目专有类型） |
| `refactor` | 不改行为的重构 |
| `docs` | 文档 |
| `test` | 测试 |
| `chore` | 构建、依赖、目录 |

示例：
```
adapt(数据层): 余票查询接口路径新增随机后缀，改由运行时探测

官方 leftTicket/query 返回 302 到带后缀的新路径，旧硬编码路径失效。
改为按响应头引导发现新路径并把结果缓存到本地配置。
对应 RISK-02。
```

**禁止**：`update`、`修改`、`fix bug` 这类无信息提交；一次提交混杂多个不相关改动。

## 三、构建与发布物

### 构建配置

| 配置 | 用途 |
|---|---|
| `Debug` | 日常开发，不分发 |
| `Release` | 分发基线 |

### 发布命令（自包含单文件）

```bash
dotnet publish src/RouteQuery.App -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

- `--self-contained true` 是**必须**的：分发对象是亲友，不能假设他们装过 .NET 运行时。
- 体积目标：压缩包 ≤ 100 MB（硬上限见 NFR）。若超预算，先考虑裁剪（`PublishTrimmed` 对 WPF 支持有限，需实测）而不是改成框架依赖。

### 发布物清单

```
RouteQuery-<版本号>-win-x64.zip
├── RouteQuery.exe
├── 使用说明.txt          ← 首次运行注意事项、如何更新站点码表、如何反馈问题
└── 变更日志.txt
```

`发布/<版本号>/` 目录只记录元信息（文件名、SHA-256、发布日期、已知问题），**不提交二进制**。

## 四、发布前检查清单

```
□ 全部 SPEC-005 手工验收项通过，测试报告已归档到 测试/报告/
□ main 分支干净，已打 tag：v<版本号>
□ 界面"关于"页版本号与 tag 一致
□ 变更日志用中文写成，面向非技术使用者（不出现类名、不出现 commit hash）
□ 站点码表内置版本已确认，并在使用说明中写明最后更新时间
□ 在另一台机器/另一个 Windows 账户上实测过一次（模拟亲友环境）
□ zip 包 SHA-256 已记录到 发布/<版本号>/说明.md
□ 合规自查：确认无自动轮询、无购票相关代码路径、无风控绕过逻辑
□ 凭据自查：全库检索确认不存在接收密码/验证码的类型或参数，日志与会话文件无明文 Cookie
□ WebView2 运行时：在目标机（含纯净 Win10）实测过内嵌登录页可用，或缺失时有明确安装引导
```

最后一项与倒数第二项是本项目独有的固定检查：功能演进时很容易顺手加"自动刷新"，而那就是合规红线的起点；凭据自查则防止"只读工具"在某次改动后悄悄开始接触他人账号。

> **grep 类检查的口径（实现阶段修正）**：URL 检查必须限定在 `.cs` 文件或显式排除 XAML 的 `xmlns` 声明——
> `xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"` 是 XML 命名空间而非网络地址，
> 不排除的话每个 WPF 文件都会命中，检查很快会被当成噪音被人跳过。**一个总是误报的检查等于没有检查。**
> 下标检查同理：允许命中落在布局描述表这一类文件内（余票列表 + 码表字段表），其余位置一律算违规。

## 五、变更日志写法（`发布/变更日志.md`）

面向亲友，不是面向开发者：

```markdown
## v1.1.0（2026-11-02）

新增
- 收藏常用线路，重启后还在，一键重查
- 结果可按"最快 / 最早出发 / 最便宜"排序

修复
- 部分夜车的到达时间显示比发车时间早的问题

注意
- 本版内置站点数据更新至 2026-10-30；若查询提示"车站未找到"，请在设置里点一次"更新站点数据"
```

**禁止**在变更日志里出现：内部编号（`FR-12`）、类名、commit 记录、未发布的功能。

## 六、回退

1. 发布后发现严重问题，24 小时内优先出修订版修复；修不动时把上一版 zip 重新发给亲友并说明"先用这一版"。
2. 不允许"静默替换"已发出的包——亲友手里的版本号必须能对应到唯一的变更日志。

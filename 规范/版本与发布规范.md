## 一、版本号规则

采用 `主.次.修订`（`1.2.0`），语义如下：

| 位 | 递增条件 | 亲友侧含义 |
|---|---|---|
| 主 | 数据格式大改、界面重构、不再兼容旧配置文件 | 需要重新设置一次 |
| 次 | 新增功能（新的筛选维度、新的方案类型） | 直接覆盖安装即可 |
| 修订 | 缺陷修复、**12306 接口字段/路径适配** | 建议尽快更新，旧版可能查不出结果 |

预发布用 `-rc1`、`-rc2`。**v1.3 起允许把 rc 作为"受控试用版"发给亲友**，但必须同时满足下面三条，缺一条就不许发：

| # | 条件 | 为什么是硬条件 |
|---|---|---|
| ① | 包内 `使用说明.txt` **第一屏**写明：这是试用件、未走完整验收、**不要拿它做购票决定**、有问题把日志文件发回 | 亲友分不清"rc"和"正式版"。这句话不在第一屏，就等于没说过 |
| ② | 发送时把"**这是试用件、没走完验收、不要拿它做购票决定**"这句原话带给对方（不是"我发给你了"就算告知）。**不要求留试用人名单** | 告知这件事本身留着；留名单不再是要件——理由见本节末"为什么撤掉名单" |
| ③ | 反馈路径固定为**日志文件**（`%LOCALAPPDATA%\RouteQuery\logs\query-日期.log`），不靠口头描述 | 本项目已经两次靠日志文本定位问题，而靠截图与描述绕了远路 |
| ④ | 正式版判据不因发过 rc 而放松：`v1.0.0` 仍要第四节清单全打勾 | 防止"发过好几版试用"被当成"已经验收过了" |

**为什么撤掉名单（v1.4）**：条件②原来还多要求一句"记录发给谁、哪一天、哪个版本与校验和"，
用意是"出问题能判断是这个包坏了还是这台机器的事"。三点让它只剩下成本——

**其一**，那份记录从来没有被填过，而**一张空表提供的诊断价值是零**，却每次出包都要为它多写一段流程。
**其二**，上面那个诊断**本来就不依赖名单**：每条日志都带版本与构建戳，
出问题的机器把日志发回来即可定位，"哪一版、什么时候"在文件里，不在表里。
**其三**更实际：留着它，"发不发"这件事上就多了一道没人想填的手续，
而收反馈的价值全在"发出去"这一步——**手续磨掉的是分发本身，不是风险**。

告知义务（条件②的前半句）与①③④一条不减：**放开的是记录，不是声明**。

`v1.0.0` 及以后的正式版才是分发给亲友的正常形态；rc 试用是**提前收集反馈的手段，不是验收的替代**。

版本号**必须**唯一来源：`src/RouteQuery.App/AssemblyInfo` 或 `.csproj` 的 `<Version>`，界面"关于"页读取同一来源。禁止在文案里手写版本号字符串。

## 二、版本控制约定

当前目录尚未初始化 Git 仓库。**第一步**就是建仓（需用户确认后执行），因为本规范的一切可追溯性都建立在提交历史上。

### 分支策略（个人/小团队规模，保持极简）

```
main            始终是可发布的状态
  └── dev       日常集成分支
        └── feat/<英文短名>   单个功能，完成即合回 dev
```

- 不长期存在的实验分支，生命周期不超过 3 天。
- 修复 12306 接口变更走 `fix/api-<日期>`，合入后立刻发修订版。

### 提交信息格式（Conventional Commits，中文描述）

```
<类型>(<范围>): <一句话中文描述>

<可选正文：为什么这么改，而不是改了什么>
```

类型取值固定：

| 类型 | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `adapt` | **适配 12306 接口变化**（本项目专有类型） |
| `refactor` | 不改行为的重构 |
| `docs` | 文档 |
| `test` | 测试 |
| `chore` | 构建、依赖、目录 |

示例：
```
adapt(数据层): 余票查询接口路径新增随机后缀，改由运行时探测

官方 leftTicket/query 返回 302 到带后缀的新路径，旧硬编码路径失效。
改为按响应头引导发现新路径并把结果缓存到本地配置。
对应 RISK-02。
```

**禁止**：`update`、`修改`、`fix bug` 这类无信息提交；一次提交混杂多个不相关改动。

## 三、构建与发布物

### 构建配置

| 配置 | 用途 |
|---|---|
| `Debug` | 日常开发，不分发 |
| `Release` | 分发基线 |

### 发布命令（自包含单文件）

```bash
dotnet publish src/RouteQuery.App -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

- `--self-contained true` 是**必须**的：分发对象是亲友，不能假设他们装过 .NET 运行时。
- 体积目标：压缩包 ≤ 100 MB（硬上限见 NFR）。若超预算，先考虑裁剪（`PublishTrimmed` 对 WPF 支持有限，需实测）而不是改成框架依赖。

### 发布物清单

```
RouteQuery-<版本号>-win-x64.zip
├── RouteQuery.exe        ← 站点码表已嵌入程序集，包内**没有** Resources/ 目录；
│                            内置表过期时由"更新站点数据"写到 %LOCALAPPDATA%\RouteQuery\stations.json
├── 使用说明.txt          ← 首次运行注意事项、如何更新站点码表、如何反馈问题
└── 变更日志.txt
```

`发布/<版本号>/` 目录只记录元信息（文件名、SHA-256、发布日期、已知问题），**不提交二进制**。

## 四、发布前检查清单

```
□ 全部 SPEC-005 手工验收项通过，测试报告已归档到 测试/报告/
□ （仅发 rc 试用版时）第一节的三条受控试用条件全部满足（v1.4 起**不再要求**试用人名单）
□ main 分支干净，已打 tag：v<版本号>
□ 界面"关于"页版本号与 tag 一致
□ 变更日志用中文写成，面向非技术使用者（不出现类名、不出现 commit hash）
□ 站点码表内置版本已确认，并在使用说明中写明最后更新时间
□ 在另一台机器/另一个 Windows 账户上实测过一次（模拟亲友环境）
□ zip 包 SHA-256 已记录到 发布/<版本号>/说明.md
□ 合规自查：确认无自动轮询、无购票相关代码路径、无风控绕过逻辑
□ 凭据自查：全库检索确认不存在接收密码/验证码的类型或参数，日志与会话文件无明文 Cookie
⊘ WebView2 运行时：在目标机（含纯净 Win10）实测过内嵌登录页可用，或缺失时有明确安装引导
   —— 本项于 2026-10-28 记为**知情风险接受**，判据与后果见本节末"⊘ 的用法"
```

### ⊘ 知情风险接受：第三种状态，以及它为什么必须存在（v1.5）

清单原本只有两态：勾上，或没勾。这在遇到"客观上做不了"的项时会退化成**永久阻塞**——
一项需要一台额外机器的检查，永远过不去，于是整张清单失去意义，
而人会开始把它当成"反正都勾不满"的仪式，连带那些**真的能做到的项**也不再被认真执行。
**一项永远勾不了的检查，等于取消了整张检查清单。**

所以加入第三态 `⊘ 知情风险接受`。它**不是**"这条不算数"，而是一条有门槛的判定：

| # | 成立条件（**全部**满足才算 ⊘，差一条就是 ☐） |
|---|---|
| ① | 缺的是**客观条件**，不是工作量：缺设备、缺环境、缺第三方配合。凡是"我们自己能做但没做"的，一律记 ☐，不许记 ⊘ |
| ② | 写清**接受的具体后果**——不是"这条不重要"，而是"如果它有问题，会坏在哪、影响到谁" |
| ③ | 写清**有没有替代证据**：同一功能在别的机器、别的账户、别的版本上验过哪一部分，剩下哪一部分是真空 |
| ④ | 由**用户本人**判定。Agent 不得自行把 ☐ 改成 ⊘，只能提出建议并摆出代价 |
| ⑤ | ⊘ **不解除披露义务**：仍要在 `发布/<版本号>/说明.md` 与随包使用说明里对使用者写明 |
| ⑥ | ⊘ **不得覆盖清单里任何"能自己做到"的项**（合规自查、凭据自查、校验和记录、变更日志、码表版本、tag）——这六项永远只能是 ☑ 或 ☐ |

**打 tag 时**：⊘ 项不阻塞，但必须在 Release 说明里逐条列出"接受了什么风险"。

### 本项的具体判定

| 项 | 内容 |
|---|---|
| 未过的检查 | WebView2 内嵌登录页在**纯净 Windows 10**（未装过 Edge 运行时）上的首启动行为 |
| 缺的客观条件 | 本机是 Windows 11，且已随 Edge 装了 Evergreen 运行时；没有 Win10 实机，也没有纯净 Win10 虚拟机 |
| 为什么不为它造条件 | 临时装系统/建 VM 的成本由个人开发者承担，且造出来的环境也不等于亲友的真实环境（亲友机器上多半已有运行时） |
| **接受的后果** | 如果某台亲友机器既没有 WebView2 运行时、又没装过 Edge，那么**登录与中转这两块功能起不来**。直达查询、筛选、经停、多买几站、收藏历史**不受影响**（它们不依赖 WebView2） |
| **已有的替代证据** | ① Windows 11 上内嵌官方登录页实测可用，且用户已在真实登录页完成过一次登录（TC-E2）；② 运行时缺失时应用**不崩**，走的是"检测到缺失 → 中文引导指向微软官方下载页"这条已实现的路径（TASK-05 的调整方案）；③ 该引导不打包进 zip，避免变成"我们分发了一个运行时" |
| 对使用者的披露 | 已写进随包使用说明"这台电脑缺少 WebView2 运行时"那一行：只影响登录，其余功能照常，并给出官方安装指引 |
| 撤销条件 | 任何时候拿到一台真实 Win10（尤其是没装过 Edge 的），跑一次登录页首启动，即可把 ⊘ 改回 ☑ |

> **这条判定对应需求侧的 RISK-19**，且与 AGENTS 第九节一致：不是拿规范当挡箭牌拒绝演进，
> 而是把"我们选择承担这个风险"写成一个**有名字、有后果、有撤销条件**的东西，
> 而不是留在"未验证"那一格里假装它迟早会被填上。

最后一项与倒数第二项是本项目独有的固定检查：功能演进时很容易顺手加"自动刷新"，而那就是合规红线的起点；凭据自查则防止"只读工具"在某次改动后悄悄开始接触他人账号。

> **grep 类检查的口径（实现阶段修正）**：URL 检查必须限定在 `.cs` 文件或显式排除 XAML 的 `xmlns` 声明——
> `xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"` 是 XML 命名空间而非网络地址，
> 不排除的话每个 WPF 文件都会命中，检查很快会被当成噪音被人跳过。**一个总是误报的检查等于没有检查。**
> 下标检查同理：允许命中落在布局描述表这一类文件内（余票列表 + 码表字段表），其余位置一律算违规。

## 五、变更日志写法（`发布/变更日志.md`）

面向亲友，不是面向开发者：

```markdown
## v1.1.0（2026-11-02）

新增
- 收藏常用线路，重启后还在，一键重查
- 结果可按"最快 / 最早出发 / 最便宜"排序

修复
- 部分夜车的到达时间显示比发车时间早的问题

注意
- 本版内置站点数据更新至 2026-10-30；若查询提示"车站未找到"，请在设置里点一次"更新站点数据"
```

**禁止**在变更日志里出现：内部编号（`FR-12`）、类名、commit 记录、未发布的功能。

## 六、回退

1. 发布后发现严重问题，24 小时内优先出修订版修复；修不动时把上一版 zip 重新发给亲友并说明"先用这一版"。
2. 不允许"静默替换"已发出的包——亲友手里的版本号必须能对应到唯一的变更日志。

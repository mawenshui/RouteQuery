## 一、分层与依赖方向

```
RouteQuery.App   ──▶  RouteQuery.Core   ◀──  RouteQuery.Data
   (UI)                (领域模型/接口)          (实现：网络/解析/缓存)
```

| 项目 | 职责 | 允许依赖 | 禁止出现 |
|---|---|---|---|
| `RouteQuery.Core` | 领域模型（车次、席别、方案、站点）、服务接口定义、纯计算逻辑（排序/筛选/历时/比价） | BCL | WPF 类型、`HttpClient`、任何 URL、任何 JSON 解析 |
| `RouteQuery.Data` | 实现 Core 的服务接口：12306 HTTP 客户端、响应解析、站点码表加载、本地缓存与配置持久化 | Core | `System.Windows.*`、View/ViewModel |
| `RouteQuery.App` | View、ViewModel、依赖注入装配、界面主题与交互 | Core（面向接口） | URL 字符串、`HttpClient`、字段下标常量 |
| `RouteQuery.Tests` | 单元与契约测试 | 全部 | 真实网络请求（见 SPEC-005） |

**必须**：UI 层只依赖 Core 的接口，通过构造函数注入；**禁止**在 ViewModel 里 `new` 一个 12306 客户端。

理由：接口一旦变化，改动被压在 `Data` 层，UI 与业务规则不受牵连——这是本项目对抗外部接口脆弱性的主要手段。

### 两条本项目特有的硬约束

1. **列下标只允许出现在一个地方**：`RouteQuery.Data` 内的版本化列布局描述表（如 `LeftTicketColumnLayout`）。解析器只通过表取列，业务代码里出现 `parts[39]` 这类裸下标即为评审打回项。自检规则（列数、车次号格式、时刻格式）同样收敛在该表附近，**不得**在 UI 层做"看起来对不对"的补救判断。
2. **凭据隔离**：WebView2 控件本身属于 `RouteQuery.App`（它是 UI），但登录能力的边界**必须**由 `RouteQuery.Core` 定义为接口（形如 `IOfficialSessionProvider`），`Data` 层只依赖该接口拿"可用的会话"。
   - **禁止**任何类型出现接收密码、验证码答案的参数或字段名（`password`、`captcha`、`code` 之类作为入参一律不允许）。
   - **禁止**在 `Data`/`App` 之外拼接登录请求；**禁止**存在登录接口 URL 常量。
   - 会话的加密/解密只允许在 `Data` 层的单一类型内完成，该类型对外不暴露 Cookie 明文集合，只暴露"给请求加上会话"这一行为。

理由：这两条把"最可能出事的两个点"（数据静默失真、凭据越界）各自钉死在一个可审计的位置，`grep` 一遍就能验证，不需要 reviewer 记住规则细节。

## 二、命名

| 元素 | 规则 | 示例 |
|---|---|---|
| 命名空间/类型/方法/属性/局部变量 | PascalCase | `TrainJourney`、`QueryDirectAsync` |
| 参数/私有字段 | camelCase，私有字段 `_` 前缀 | `_httpClient`、`travelDate` |
| 常量 | PascalCase | `DefaultTimeout` |
| 接口 | `I` 前缀 | `ITrainQueryService` |
| 异步方法 | `Async` 结尾 | `LoadStationsAsync` |
| ViewModel | `XxxViewModel` | `QueryResultViewModel` |
| 枚举成员 | PascalCase，值语义明确 | `SeatClass.SecondClass` |
| 布尔 | `Is/Has/Can` 前缀 | `IsDirect`、`HasTicket` |

**禁止**：拼音命名（`checi`、`yupiao`）、无意义缩写（`tmp2`、`data3`）、中文标识符。中文只出现在注释、界面文案、文档里。

## 三、注释（中文）

1. 注释一律用中文；代码标识符保持英文。
2. 公共类型的 XML 文档注释 `<summary>` 用中文一句话说明"它代表什么业务含义"，并**回指需求编号**：

```csharp
/// <summary>
/// 直达列车查询结果。对应 FR-08（直达车次列表）。
/// </summary>
public sealed class TrainJourney { }
```

3. 内部注释默认不写。只在以下情形写，且一句话说清：
   - 非显然的外部约束（例：`// 12306 该字段可能缺失，缺失时按"无票"处理`）
   - 隐藏不变量
   - 针对具体缺陷的临时规避手段，附现象描述
4. **禁止**写"WHAT 型"注释（`// 设置 name 为 xxx`）、禁止写任务/PR 编号型注释（`// 用于处理 issue#123`）——这类信息属于提交信息与开发日志。
5. **禁止**留被注释掉的死代码提交进仓库。

## 四、异步、取消与错误处理

### 异步

- 所有 I/O 方法签名 `Task<T>` / `ValueTask`，接受 `CancellationToken`。
- **禁止** `.Result`、`.Wait()`、`async void`（除 WPF 事件处理器）。
- ViewModel 里的命令用 `IAsyncRelayCommand` 风格封装；事件处理器是唯一允许 `async void` 的地方，且**必须** try-catch 兜底并转成界面提示。

### 网络调用三件套（必须齐备）

```csharp
using var cts = CancellationTokenSource linkedTo(_userCancellation, timeout: TimeSpan.FromSeconds(15));
```

1. **超时**：连接/读取超时必须显式设置，不依赖默认值。
2. **取消**：界面提供"取消查询"，切换查询条件时旧请求必须被取消，禁止旧结果覆盖新结果（用请求序号或 `CancellationToken` 判定）。
3. **降级**：捕获后转成领域错误类型（见下），禁止把 `HttpRequestException` 抛到界面。

### 错误分类

`Core` 定义错误种类，`Data` 负责把技术异常映射进去，`App` 只按种类给文案：

| 错误类型 | 含义 | 界面应做什么 |
|---|---|---|
| `NetworkUnavailable` | 断网/DNS/TLS | 提示检查网络，提供"重试" |
| `UpstreamRejected` | 被风控或返回非预期结构 | **停止自动重试**，提示"官方接口暂时不可用，请稍后再试" |
| `ParseFailure` | 接口结构变更 | 提示"官方数据格式变更，需升级本工具"，并写入本地日志 |
| `NoResult` | 无车次 | 正常空状态，不是错误 |
| `InputInvalid` | 输入不合法 | 定位到具体输入框 |

`ParseFailure` 单列一类，是因为它决定了这个应用能否被亲友自助修复——日志里必须落原始响应片段（脱敏后）以便新版本修复。

## 五、WPF / MVVM 具体约定

1. 界面用 XAML，样式与模板集中在 `Theme/` 资源字典，**禁止**在 View 的 code-behind 写业务逻辑（`code-behind` 只允许控件级处理，如获取焦点、滚动定位）。
2. ViewModel **禁止**引用 `System.Windows` 类型（`Visibility`、`Brush` 等）。需要时通过值转换器在 XAML 侧转换。
3. 长列表**必须**开启虚拟化（`VirtualizingStackPanel`），车次结果按当前预售期数据量级验证过 60 条以上不卡顿。
4. 站点选择用可搜索下拉，禁止让用户手记三字码。
5. 用户可见文案集中在 `RouteQuery.App/Resources/文案.xaml` 的资源字典里按用途命名，XAML 用 `DynamicResource` 引用；**禁止**把提示语硬编码在控件属性或 code-behind 字符串里——分散的文案既改不动也走查不全。
6. 数值/时刻的展示格式化放在展示层，`Core` 里保持原始类型（`TimeSpan`、`DateOnly`、`decimal`）。

## 六、数据与时间

1. 日期一律用 `DateOnly`，时刻用 `TimeSpan` 或 `TimeOnly`；**禁止**用 `string` 承载日期在层间传递。
2. 票价用 `decimal`，**禁止** `double`/`float`。
3. 历时用 `TimeSpan`，不存"分钟数 int"再换算。
4. 时区：12306 数据均为北京时间，本地不做时区换算，但**必须**在解析层显式注明"按北京时间处理，不做转换"，避免后人加 `ToLocalTime()`。
5. 夜车跨零点（发车 23:xx、到达次日）必须在数据模型上有明确表达字段，不能靠"到达时间小于发车时间就是次日"这种推断散落在 UI。

## 七、依赖引入纪律

1. 新增 NuGet 包**必须**在设计文档记录：包名、用途、为什么不能自己写 20 行解决、维护活跃度。
2. 允许的默认选型：`CommunityToolkit.Mvvm`、`Microsoft.Extensions.DependencyInjection`、`System.Text.Json`、`Microsoft.Web.WebView2`（仅用于内嵌官方登录页，见 SPEC-007 第三节）、`System.Security.Cryptography.ProtectedData`（DPAPI 会话加密）。
3. **禁止**为图标/图表/特效引入体积远超功能价值的包。
4. 缓存与配置用本地文件（`%LOCALAPPDATA%`），**禁止**为此拉入完整 ORM。
5. WebView2 运行时在 Windows 11 随系统提供，Windows 10 需 Evergreen/离线安装。**引入该依赖前必须**确认：目标亲友机的运行时可用性、缺失时的安装引导文案、以及"固定版本"与包体积的取舍。

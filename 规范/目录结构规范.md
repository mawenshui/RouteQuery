## 一、设计原则

1. **文档目录用中文，代码目录用英文。** 文档给人读，中文最直接；代码受编译器、MSBuild、路径编码约束，ASCII 更稳。
2. **按"文档生命周期"分目录，不按"文档类型"堆在一起。** 需求、设计、计划、测试、发布各自归位，一眼能看出项目走到哪一步。
3. **根目录保持克制。** 只允许三个文件：`AGENTS.md`、`README.md`、`.gitignore`。
4. **一个目录超过 15 个文件就考虑分子目录**，但不要提前分。

## 三、每个目录的准入判定

| 想放的东西 | 放哪儿 | 常见错误 |
|---|---|---|
| 功能需求、验收标准 | `需求/` | 写进设计文档里，导致"改代码顺手改需求" |
| 架构图、模块划分、数据模型、字段映射表 | `设计/` | 写进代码注释，代码一删就没了 |
| 任务拆分、实现顺序、当前做到哪 | `计划/` | 用聊天记忆代替计划 |
| 为什么选 A 不选 B | `开发日志/` | 散落在多个文档里，事后无法还原 |
| 手工测试步骤、验收打勾表 | `测试/用例/` | 只存在于脑中，验收时扯皮 |
| 12306 返回样本 | `测试/接口样本/` | 硬编码在测试源码里，diff 巨大 |
| 给用户看的更新说明 | `发布/变更日志.md` | 用提交信息当发布说明 |
| 临时脚本、抓包草稿 | 用完即删，或写入 `开发日志/` | 建 `临时/`、`test/`、`备份/` 目录 |

**禁止**新建下列目录：`临时/`、`新建文件夹/`、`备份/`、`old/`、`docs1/`、`.notuse/`。需要保留旧版文档时，靠版本号和变更记录，不靠复制文件。

## 四、文件命名规则

### 文档文件

格式：`YYYY-MM-DD-<主题>-<类型>.md`

- 日期取**该文档首次定稿的日期**，后续修订不改文件名，只改文档头的版本字段。
- 主题使用简短中文词组，不超过 12 字。
- 类型取自固定集合：`需求文档` / `系统设计` / `实施计划` / `测试用例` / `测试报告` / `设计`。
- 长期演进的单例文档可不带日期：`规范总览.md`、`变更记录.md`、`变更日志.md`。

示例：
```
2026-10-09-列车线路查询应用-需求文档.md      ✅
2026-10-09-列车线路查询应用-系统设计.md      ✅
需求文档-最终-最终v2-修改版.md               ❌
```

### 代码文件

- C# 源文件 `PascalCase.cs`，与主类型同名。
- ViewModel 以 `ViewModel` 结尾，View 以 `View.xaml` 或 `Page` 结尾。
- 测试文件 `<被测类名>Tests.cs`。

---

## 五、二进制与大文件

1. 本仓库**不提交**编译产物：`bin/`、`obj/`、`*.exe`、`*.dll`、`*.msi`、`*.zip` 一律进 `.gitignore`。
2. 发布物走本地目录或网盘，`发布/<版本号>/` 里只放一份中文说明文件，记录：版本号、发布日期、文件名称、SHA-256、已知问题。
3. 图标等必要素材放 `素材/`，单文件不超过 2 MB。
4. `测试/接口样本/` 里的 JSON **必须脱敏**：删除或替换 Cookie、IP、账号标识后再提交。

## 六、目录初始化清单（新项目落地时按此顺序建）

```
规范/  需求/  设计/界面/  计划/  开发日志/  测试/用例/  测试/报告/  测试/接口样本/  发布/  素材/  src/
```

空目录不预建 `.gitkeep`；等真的有第一个文件时再建目录，避免仓库结构看起来比实际进度更丰满。

## 一、测试数据（固定，便于复现）

| 代号 | 内容 | 用来验什么 |

## 二、执行清单

### A 组：输入与校验（FR-01 ~ FR-04）

| 编号 | 步骤 | 通过判据 |
|---|---|---|
| TC-A1 | 出发站输入 `北京` | 候选 ≥ 4 条（北京/北京南/北京西/北京朝阳…），每条显示**全称**，无合并项 |
| TC-A2 | 输入 `bjn` | 首位命中"北京南" |
| TC-A3 | 输入 `zzz不存在的站` | 显示未命中引导文案，**不是空列表** |
| TC-A4 | 键盘 ↓ ↓ Enter | 选中第三项，无需鼠标 |
| TC-A5 | 选好后在框内重新输入 | 旧三字码状态被清空，不残留 |
| TC-A6 | 点互换按钮 | 两站互换，日期与筛选条件不变，结果区清空但不报错 |
| TC-A7 | 打开日期控件 | 今天之前与预售期之外全部置灰；每个日期显示星期 |
| TC-A8 | **六项非法输入逐一构造**：出发站空 / 到达站空 / 两站相同（用 OD-D 改成同站）/ 日期昨天 / 日期超预售期 / 码表未加载 | **官方请求发出次数为 0**（拔网线或看日志均可验证），且每种都有定位到具体输入框的提示 |
| TC-A9 | 3 秒内连点查询 10 次 | 实发官方请求 ≤ 1 次，其余给出"稍等几秒再查询"提示，**不排队积压** |

TC-A8 是全场最重要的一条：它验证"校验发生在网络之前"。做不出"零请求"的证据，就等于没验证。

### B 组：查询与余票正确性（FR-05、FR-09、FR-13）

| 编号 | 步骤 | 通过判据 |
|---|---|---|
| TC-B1 | OD-A 查询 | 结果条数与官方页面一致；任取 3 趟车核对发到时刻、历时、站名一致 |
| TC-B2 | OD-B 查询（含普速） | K/T/Z 车次的席别名与余票值与官方逐格一致；**候补显示为"候补"而不是"有"** |
| TC-B3 | 把日期推到预售期边界内外各查一次 | 边界内可查、边界外被本地拒绝；上界值与 `settings` 配置一致 |
| TC-B4 | 任取一趟夜车（到达时刻早于出发） | 显示"次日"，历时按 +24h 计算 |
| TC-B5 | 核对最低价与席别票价 | 与官方票价一致；无座价 = 同席别座席价，**不显示为空** |
| TC-B6 | 喂入异常样本（列数 57 / 时刻列非 `HH:mm`） | 显示"数据格式有变化…请找我要新版"，**不渲染任何车次行** |
| TC-B7 | 断网查询 → 恢复后再查询 | 断网时文案为"连不上网络"且可重试；恢复后重试成功 |

### C 组：筛选与排序（FR-11、FR-12）

| 编号 | 步骤 | 通过判据 |
|---|---|---|
| TC-C1 | 只看有票 + 只看高铁 + 上午 三条件叠加 | 结果正确；**候补车次不出现在"只看有票"结果中** |
| TC-C2 | 切换排序五键 | 首条即时变化、滚动回顶；同值时按出发时刻次级排序 |
| TC-C3 | 对"最低价"排序且存在无价车次 | 无价车次排在有价之后并标 `—`，**不被当成 0 元排到最前** |
| TC-C4 | 筛选后结果为空 | 文案是"当前筛选条件下没有车次" + 清除筛选，**不是"无直达车次"** |
| TC-C5 | 拔网线后做全部筛选与排序 | 全部可用，无网络请求 |

### D 组：钻取与区间扩展（FR-14、FR-26 ~ FR-31）

| 编号 | 步骤 | 通过判据 |
|---|---|---|
| TC-D1 | 展开 ST-1 经停时刻表 | 32 站顺序与官方一致；当前 OD 两站高亮；不触发额外余票查询 |
| TC-D2 | 展开另一车次 | 上一个面板自动收起 |
| TC-D3 | 对一趟不可网上购票的车次点"多买几站"（K=3） | 显示预估耗时与进度；结果逐条即时插入；每条同屏可见"多买 X 站"与"多花 ¥Y" |
| TC-D4 | 批次执行中点"停止" | 已获结果保留可见；不再发新请求 |
| TC-D5 | 批次中注入风控响应 | **整批立即中止**，文案为"过几分钟再试"且无重试按钮刷屏；直达区不受影响 |
| TC-D6 | 上限依次设为 1 / 10 / 0 / 11 / 空 / `abc` | 非法值被拒或钳到边界；候选数与预估耗时随 K 变化 |
| TC-D7 | 把预算配置改成 99 后重复 TC-D3 | 实际官方请求数**仍 ≤ 12**（硬钳制在代码层，不信任配置） |
| TC-D8 | 对一趟"全程票"车次（OD 即始发→终到）点扩展 | 候选为 0，显示"已是全程票，无法再扩展"，**官方请求数为 0** |
| TC-D9 | 逐条核对 Δ | 至少 3 车次 × 2 候选：用官方页面分别查两个区间票价手工相减，Δ 一致；缺失处显示"无法计算"；**全程不出现 0 或负数** |
| TC-D10 | 看中转方案卡片 | 两段各自可展开经停；换乘候车时长与两段时间自洽；**中转段无扩展入口** |

### E 组：登录与会话（FR-24、FR-25）

| 编号 | 步骤 | 通过判据 |
|---|---|---|
| TC-E1 | 未登录点中转页签 | **引导态**（中性色 + 登录按钮），非错误态；文案说明"不登录也能查直达" |
| TC-E2 | 点"登录" | 打开的是官方登录页，页内域名可见可核对；**应用内没有任何输入密码的界面** |
| TC-E3 | 登录成功后查中转 | 中转出数据；状态栏显示"已登录" |
| TC-E4 | 点"清除登录状态" | 中转立刻回未登录态；`session.protected` 被删除或清空 |
| TC-E5 | 全盘检索本机存储与当日日志 | 检索不到明文 Cookie；日志无 Cookie 字符串 |
| TC-E6 | 会话过期（官方侧失效）后查询 | 应用清掉本地会话并提示需重新登录，**不静默重登、不反复撞** |

### F 组：本地数据、可用性与分发（FR-16 ~ FR-23）

| 编号 | 步骤 | 通过判据 |
|---|---|---|
| TC-F1 | 保存 5 条常用线路 → 关闭 → 重启 | 全部仍在；点击可一键回填 OD（日期不回填） |
| TC-F2 | 保存到第 21 条 | 明确提示已达上限，**不是静默丢弃** |
| TC-F3 | 查 35 条历史 → 重启 | 只保留最近 30 条，最旧的被淘汰 |
| TC-F4 | 设置页"清空本地数据" | 二次确认；确认后收藏/历史/缓存确实从文件层面消失 |
| TC-F5 | 首次启动 | 出现一次非官方声明确认；再次启动不再弹；声明常驻状态栏 |
| TC-F6 | 冷启动计时 | 主窗口出现 ≤ 2 秒，无白屏闪烁 |
| TC-F7 | 100% / 125% / 150% 三档缩放截图 | 文字不截断、按钮不重叠 |
| TC-F8 | **干净 Windows 账户**安装发布 zip | 双击可用，无需另装运行库；含 `使用说明.txt` |
| TC-F9 | **请一位亲友在无人指导下完成首次查询** | ≤ 30 秒（NFR-10）。做不到就是缺陷，不是"对方不会用" |

## 三、发布前对照

以上 41 条全部执行后，逐条填 `测试/报告/<版本>-验收报告.md`：通过 / 失败 / **未验证 + 原因** 三态之一。

三条红线：

1. 不允许把"未验证"记成"通过"。客观做不到的（如缺一台干净机器）就写未验证并说明原因。
2. B 组与 D 组各有一条失败即**不得发布**（数据正确性与金额正确性，NFR-16 / NFR-18）。
3. E 组任一条失败即**不得发布**——涉及他人账号会话的安全性质，不适用"下次修"。
